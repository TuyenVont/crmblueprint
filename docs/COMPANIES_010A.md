# PHASE 010A - Companies Read

Implemented /app/companies and /app/companies/[id]. The user request was the assigned task; tasks/ contains only the foundation ticket.

## Reused architecture

Contacts server services, getAppContext, cookie-authenticated publishable-key Supabase client, effective permission sets, generic DataTable, SearchForm, Pagination, desktop table/mobile cards, loading/error/unavailable route boundaries. SearchForm gained an optional label, retaining the Contacts default. No dependencies or company mutations were added.

## Authorization and queries

Every entry point derives the active workspace and permissions from getAppContext. COMPANIES_VIEW is mandatory, without role-name checks. All business queries explicitly filter workspace_id from that context. Missing, malformed and foreign company IDs use identical notFound behavior; raw database errors are replaced with generic messages. No service-role client is used.

Companies selects explicitly allowlist existing schema fields. Search uses escaped literal case-insensitive substrings across name, email and phone, with a 200-character maximum. Pagination follows Contacts: exact filtered total, 50 rows, created_at descending then id ascending. Offset pagination is deterministic for unchanged data; concurrent inserts/deletes may shift page boundaries. New searches reset the page and pagination retains the search. Empty workspace, no matches and out-of-range pages have separate messages.

Linked contacts use company_contacts and its existing composite contact foreign key, with an inner embed. The server does not query relationships or contact fields without CONTACTS_VIEW, and the UI explains that restriction. Linked contacts are also paginated in batches of 50 with exact count and deterministic ordering. No contacts.company_id or other table/column changes.

## Blocking security issue and migration

Existing companies_manage_authorized and company_contacts_manage_authorized are permissive FOR ALL policies: these also grant SELECT, bypassing the separate view policies for manage-only roles. Apply supabase/migrations/20260916001100_companies_read_guards.sql before deploying. It adds restrictive SELECT policies requiring COMPANIES_VIEW on companies and both view permissions on company_contacts. Existing composite foreign keys enforce same-workspace relationships. The migration changes policies only, not table structure or mutation APIs. Applied to the local disposable PostgreSQL instance only; hosted deployment and schema parity remain unverified.
